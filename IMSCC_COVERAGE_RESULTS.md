## Root Causes (8 patterns)

These Pandoc/conversion behaviors cause the normalization mismatch. Fixing any of these in the script would reduce the false-miss rate:

### 1. Backslash-escaped apostrophes (most common)
Pandoc escapes apostrophes as `\'` in many contexts. The IMSCC has `you'll` but the Markdown has `you\'ll`. The `_normalize()` function decodes HTML entities but does not strip backslash escapes.

Example — "Worksheets For Lecture 01":
```
IMSCC:    you'll need to show that you've made a successful effort
Markdown: you\'ll need to show that you\'ve made a successful effort
```

### 2. Canvas internal link placeholders with attributes
The IMSCC link rewriter replaces `$CANVAS_OBJECT_REFERENCE$` tokens but leaves the full Markdown link with all its attributes inline: `[link text]($WIKI_REFERENCE$/pages/...){course-type="..." api-endpoint="..." api-returntype="..."}`. Any fragment that spans across a link sees this attribute blob inserted in the middle.

Example — "Week 10 Pre-Class Notes":
```
IMSCC:    review the Pre-Class Notes Policy for full instructions. Pre-Lecture Material
Markdown: review the [Pre-Class Notes Policy]($WIKI_REFERENCE$/pages/g...){course-type="wikiPages"
          published="false" api-endpoint="..."} for full instructions.
          ## Pre-Lecture Material
```

### 3. HTML style/span attributes in Markdown output
Pandoc preserves `{style="font-size: 24pt;"}` and `{style="text-decoration: underline;"}` etc. as raw Markdown span attributes, injecting them into the text stream.

Example — "Coding Exercises: Week 04 Pre-Work":
```
IMSCC:    WARNING: You should plan on taking the midterm and final
Markdown: ## **[WARNING: ]{style="font-size: 24pt;"}**
          [**You should plan on taking the midterm and final...
```

### 4. List/heading markers inserted between content
When a fragment spans two adjacent list items or headings, the bullet marker (`-   `, `1.  `, `##`) is inserted in the middle, breaking the substring match.

Example — "02 Pre-Lecture Materials":
```
IMSCC:    Nested For Loops How to produce complex figures using nested
Markdown: 1.  [Nested For Loops](https://youtube.com/...){...}
          2.  [How to produce complex figures using nested loops](...)
```

### 5. Pandoc hard line-break markers (`\`)
Pandoc emits a trailing `\` to represent hard line breaks. The `_normalize()` function collapses whitespace but leaves the `\` character, so `963 064 1262\` does not match `963 064 1262`.

Example — "Zoom Links":
```
IMSCC:    ID: 963 064 1262 One tap mobile +12532158782,,9630641262# US (Tacoma)
Markdown: Meeting ID: 963 064 1262\
          One tap mobile\
          +12532158782,,9630641262# US (Tacoma)
```

### 6. Escaped special characters (`\"`, `\<`, `\|`, `\[`, etc.)
Pandoc escapes angle brackets, pipes, brackets, and quotes with backslashes. These stay in the normalized text.

Example — "Week 8 In-Person Activities":
```
IMSCC:    in the following format <snip>.Write a modified version of the
Markdown: in the following format \<snip\>.Write a modified version of the
```

### 7. Code whitespace differences
HTML source code blocks with extra spaces inside (e.g., `method1 ( )`) become `method1( )` in the Markdown (or vice versa). After whitespace normalization, the internal space difference remains.

Example — "Coding Exercises: Lecture 01 Review":
```
IMSCC:    method1 ( ) ; } public static void method1 ()
Markdown: method1( ) ;
```

### 8. Heading anchor attributes
Canvas-generated headings sometimes produce Pandoc output like `## heading {#anchor data-start="510" end="548"}`, inserting the anchor attributes into the normalized text stream.

Example — "In-Class Participation Policy":
```
IMSCC:    how it works: ✅ 1. Review Notes Time (1 pt)
Markdown: ### [✅ 1. **Review Notes Time (1 pt)**]{style="font-size: 14pt;"}
          {#review-notes-time-1-pt data-start="510" end="548"}
```

## Recommended Script Fixes

To reduce the false-miss rate, the `_normalize()` function in `scripts/check_imscc_coverage.py` should be extended to handle these Pandoc artifacts:

1. **Strip backslash escapes**: Replace `\'` → `'`, `\"` → `"`, `\<` → `<`, `\>` → `>`, `\|` → `|`, `\[` → `[`, `\]` → `]` before comparing.
2. **Strip Markdown link syntax**: Replace `[text](url){attrs}` with just `text` so link attributes don't pollute the match.
3. **Strip `\` hard line-break markers**: Replace trailing `\` (line continuation) with a space.
4. **Strip Markdown heading markers**: Remove leading `##`, `###` etc.
5. **Strip Markdown list markers**: Remove leading `-   `, `*   `, `1.  ` etc.
6. **Strip `{...}` attribute blocks**: Remove span attribute blocks like `{style="..."}` and `{#anchor data-start="..."}`.

Implementing fixes 1, 3, and 6 alone would resolve the majority of misses (root causes 1, 5, 3, 8). Fixes 2, 4, 5 would handle the remaining structural ones.
